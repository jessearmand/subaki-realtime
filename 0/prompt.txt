## 3. The LM leg — exact wire format (what you'd swap for Tinker/Inkling)

**Client → `/api/llm`** (`use-cascade-session.ts:290-301`):

```jsonc
POST /api/llm            // Content-Type: application/json
{ "backend": a.lmBackend, "model": a.lmModel,
  "messages": [{role:"system",content:instructions}, ...history],  // roles: system|user|assistant
  "maxTokens": a.maxTokens, "temperature": a.temperature }
```

**Route → upstream** (`app/api/llm/route.ts:61-85`) — plain OpenAI chat-completions, always streaming:

```jsonc
POST &lt;backend.url&gt;
Authorization: Bearer &lt;process.env[backend.envKey]&gt;   // omitted entirely when envKey === ""
Content-Type: application/json
Accept: text/event-stream
{ "model": body.model, "messages": [...], "stream": true,
  "max_tokens": body.maxTokens ?? 256, "temperature": body.temperature ?? 0.7,
  // only when backend.supportsThinking:
  "chat_template_kwargs": { "enable_thinking": false } }
```

**Response**: the upstream SSE body is piped back verbatim (`route.ts:104-111`, `Content-Type: text/event-stream`). The client parses only `data:` lines and reads `JSON.parse(data)?.choices?.[0]?.delta?.content` (`use-cascade-session.ts:315-330`), skipping `[DONE]`. Nothing else in the SSE payload is used — no `reasoning`, no tool calls, no usage.

Implications for swapping in another endpoint:
- **OpenAI-compatible endpoint (e.g. Tinker/Inkling if it exposes `/v1/chat/completions` SSE)**: zero code change — add a `backends` entry (`url` + `envKey: "TINKER_API_KEY"` + `supportsThinking`) and a `models` entry in `config/lm-models.json`. `TINKER_API_KEY` is already declared in `/Users/jessearmand/Develop/realtime-persona/fnox.toml:48` (currently uncommitted, and note it's wired to the `ElevenLabs` keychain provider at that line — likely a copy/paste you'll want to point at a `tinker` provider block, which exists at `fnox.toml:35-37`).
- **Anthropic-shaped endpoint**: needs code. The two things that are OpenAI-specific are the upstream body build (`app/api/llm/route.ts:61-73` — `max_tokens` is fine, but Anthropic requires `system` hoisted out of `messages` and `anthropic-version` + `x-api-key` headers) and the delta parse (`use-cascade-session.ts:322`, which expects `choices[0].delta.content` rather than `content_block_delta`/`text_delta`). Cleanest seam: add a `shape: "openai" | "anthropic"` field to `LmBackendConfig` (`lib/realtime/lm-config.ts:12-21`), branch the request build in the route, and translate Anthropic SSE → OpenAI-shaped `data:` frames inside the route so the client parser stays unchanged.

Also relevant: the route hard-requires `model` + non-empty `messages` (`route.ts:57-59`) and 500s if a *named* `envKey` is unset (`:50-56`); an empty `envKey` means keyless.
